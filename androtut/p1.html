Android programming

1. Getting started

The entire process is quite simple in principle, but rendered rather complex by Google. I shall present things in a order that should seem natural to a programmer.

First, the aim: Our hello world app should write "Hello world" on the mobile screen, and that's it.

Here are the main steps:
  1. The first step is of course to write the program, i.e., create source code as a text file. There is nothing unexpected in this. What is unexpected, however, is that here we have to create at least two text files, a java file containing the main program and an xml file containing certain overall information about the program. For most non-trivial programs you will also have a third file, which is yet another xml file describing the GUI.
  2. The second step is to compile it. The compilation occurs in multiple phases. The first phase is our familiar javac. Then we also need to compile the xml files, and then we have to link all these things. The resulting binary needs to be further translated to dex code, and then processed further.
  3. The final step is to download the code into the mobile and install it. Of course, we may consider the downloading and the installing as different phases. But we shall use a single command that will do both the things in one go.

1.1. A few more details

Before starting writing our code, let me give you a few more details regarding the last two phases. The compilation turns your source files into binary files suitable for your mobile. Clearly, this binary depends on the version of Android running in your mobile. So you need have in your laptop some build tools specific to the Andorid running in your mobile.

In the third phase the mobile needs to be put into a programmable mode which is called "debug mode".

We shall start by making sure that we have all the build-tools ready. The build-tools are of two flavours: those which depend on the Android version running on your mobile, and those that don't. First, the ones that don't. They are jdk, zip and latest-commandline-tools. The versions of these are not crucial, but good to have recent versions. The first two are already familiar. The last one you can get from here.

Next for the platform specific tools. Before obtaining them you need to know the Android version in your phone. Then translate that version to another number called the build number using the mapping in this page. Google has made the next step tricky. The platform specific tools are in two zip files at public URLs. But Google keeps these URLs secret. In fact, it stores these URLs in a publicly available xml file, whose name is not public. This name is hardcoded in an indirect way in one of the platform independent files. However, there is a script called the sdkmanager which can supposedly be used to download both these zip files without having to explicitly specify the URLs. But this script is buggy. It claims to be deprecated, while its suggested relacment also claims itself to be deprecated. However, a little patient querying will cause ChatGPT to yield the correct URLs, and you can download them.

Place them in their proper places, and you are all set.
